# Dreamie MVP：本地用户与记忆设计

## 目标

让 Dreamie 在不要求登录、不同步云端、不过度保存私密对话的前提下，逐步学习一位本地用户的睡前偏好，并在下次背景音推荐时使用这些偏好。

本阶段不实现账号体系、跨设备同步、向量检索、睡眠医疗判断或自动推断真实睡眠时长。

## 决策与约束

- 只支持一位本机用户，固定标识为 `local-user`。
- 使用现有 Node 运行时内置的 `node:sqlite`；不新增第三方数据库依赖。
- 数据库文件位于 `data/dreamie.db`，并加入 Git 忽略规则。
- 默认不持久化完整对话原文。运行时只保留当前会话最近六轮；会话结束后持久化结构化事件和简短摘要。
- 用户可以在后续版本查看、删除或导出自己的本地数据；本阶段先提供程序化清除入口。

## 数据模型

### `user_profile`

一行，记录稳定设置：

- `user_id`：固定为 `local-user`
- `timezone`：默认 `Asia/Shanghai`
- `voice_id`、`voice_speed`：用户主动设置的 TTS 偏好
- `created_at`、`updated_at`

### `sessions`

每晚一次睡前会话：

- `id`、`user_id`
- `started_at`、`ended_at`
- `mood`：本轮最后一次由模型识别的状态
- `summary`：最多 300 字的睡前状态摘要；不保存逐字聊天记录

### `listening_events`

每次背景音决策的可审计行为：

- `id`、`session_id`、`user_id`
- `track_id`
- `event_type`：`recommended`、`played`、`changed`、`liked`、`disliked`
- `created_at`

### `memory_items`

可被下一次推荐检索的稳定记忆：

- `id`、`user_id`
- `key`：例如 `preferred_audio_kind`、`disliked_track_id`
- `value`：例如 `rain`、`asmr-microphone-biting`
- `polarity`：`positive` 或 `negative`
- `confidence`：0 到 1
- `evidence_count`
- `source`：`explicit`（用户明确表达）或 `behavioral`（重复行为）
- `last_confirmed_at`、`created_at`、`updated_at`

## 写入规则

| 输入或行为 | 写入内容 |
| --- | --- |
| 推荐某段背景音 | 新增 `recommended` 事件 |
| 用户确认播放 | 新增 `played` 事件 |
| 用户输入“换一个” | 为刚才的音频新增 `changed` 事件；不直接视为永久不喜欢 |
| 用户输入“喜欢” | 新增 `liked` 事件，并提高对应类型的正向记忆置信度 |
| 用户输入“不喜欢”“不要再推荐” | 新增 `disliked` 事件，写入高置信度负向记忆 |
| 同一类型累计三次播放或喜欢 | 创建或升级 `behavioral` 正向记忆 |
| 用户明确说“记住，我喜欢/不喜欢…” | 创建或覆盖 `explicit` 记忆 |

无论何种情况，用户仅表达当晚感受（例如“今天很累”）时，默认不写入长期记忆。

## 读取与推荐流程

1. Dreamie 启动会话并创建 `session`。
2. 查询用户档案、有效的长期记忆，以及近 14 天的播放/换歌统计。
3. 将这些内容压缩成短摘要，并与当前会话最近六轮对话一起传给模型。
4. 模型返回当前 `mood`；推荐器从本地音频目录中排除负向记忆和当前会话已拒绝的曲目，再为符合情绪和偏好的曲目排序。
5. Dreamie 展示推荐，等待明确确认后才播放。
6. 记录推荐、播放、换歌、喜欢或不喜欢事件；会话结束时保存摘要和最后状态。

推荐优先级：明确负向记忆排除 > 当前会话的“换一个”排除 > 明确正向偏好 > 近期多次播放 > 情绪匹配 > 音频目录默认顺序。

## 模块边界

- `memory-store.ts`：初始化 SQLite、读写表、事务与清除本地数据。
- `memory-policy.ts`：将用户反馈和事件转换为记忆更新，避免将全部聊天写入长期记忆。
- `recommendation-context.ts`：将档案、长期记忆、近期行为压缩为模型上下文与排序输入。
- `background-audio-flow.ts`：调用上述模块，保持终端交互和播放器职责不变。

## 错误与隐私处理

- 数据库无法创建或写入时，仍可进行当晚推荐与播放，但输出简短提示“本次偏好未保存”。
- 缺失或损坏数据视为空记忆，自动创建必要表；不删除音频文件。
- 不向 DeepSeek 发送数据库原始记录、音频文件路径或完整历史对话，只发送经过压缩的偏好摘要和当前会话上下文。
- 数据库文件和未来导出文件均不进入 Git。

## 验收与测试

1. 新用户可自动初始化本地数据库与 `local-user` 档案。
2. 播放、换一个、喜欢、不喜欢分别生成正确事件。
3. 三次正向行为会建立对应长期偏好；一次换歌不会建立负向长期偏好。
4. 明确“不喜欢”会在下次推荐中排除对应曲目或类型。
5. 推荐上下文只包含允许的摘要和最近六轮，不包含完整历史库。
6. 数据库写入失败时，对话与播放仍可继续。
7. 全部既有测试及新增测试通过，TypeScript 检查通过。

## 不在本阶段

- 多用户登录和云端同步
- 用户界面、数据报表、自动定时关闭
- 情绪或睡眠疾病诊断
- RAG、Embedding、向量数据库
- TTS 与背景音混音
