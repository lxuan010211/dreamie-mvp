# Dreamie 音频编排与自然推荐设计

## 目标

让 Dreamie 根据用户当下意图灵活选择陪伴方式：普通聊天使用语音回复；用户明确需要时播放背景音；用户要求故事或冥想并希望有氛围时，将 TTS 与背景音一起播放。同时保留适度的主动推荐，但避免每次回复都推荐音频。

## 用户体验规则

### 音频模式

- `voice`：普通聊天、情绪陪伴、待办整理和一般问答，只播放 Dreamie 的 TTS。
- `background`：用户明确要求雨声、白噪音、海浪或其他背景音时，播放一条匹配的背景音。
- `voice_with_background`：用户明确要求故事/冥想并要求配背景音时，生成 TTS，并与背景音同步播放。
- 没有明确音频需求时，默认使用 `voice`，不附带背景音推荐。

### 主动推荐

- 只有在识别到明显疲惫、焦虑、脑内反刍或入睡困难，并且推荐与用户历史偏好匹配时，才进行一次轻量建议。
- 推荐使用陪伴式表达，例如“如果你愿意，我可以让一点雨声陪着你；不想听也没关系，我们继续聊”，不使用菜单式连续推销。
- 每轮最多建议一次；用户明确拒绝后，本次会话进入推荐冷却，不再重复建议。
- 用户明确说“播放”“加一点背景音”等指令时，直接进入对应模式，不再额外询问。
- 推荐、接受、拒绝、跳过、喜欢和不喜欢都记录为行为事件，用于后续个性化，但不影响当前文字回复。

## 系统结构

### Agent 输出

在现有睡前计划基础上增加音频编排字段：

```json
{
  "audioMode": "voice | background | voice_with_background",
  "audioScript": "需要朗读的内容",
  "backgroundTrackId": "可选的背景音目录 ID",
  "recommendation": "可选的自然推荐句",
  "autoplay": "true | false"
}
```

Agent 只负责判断意图和生成脚本；背景音必须从现有安全目录选择，不能让模型生成任意文件路径。

### 后端

- 保留现有 MiniMax TTS 服务端调用，服务端返回浏览器可播放的音频数据。
- 扩展睡前计划解析和 Web 会话响应，使其返回音频模式、脚本、背景音 ID 和推荐文本。
- 只有 `background` 或 `voice_with_background` 模式才附带背景音资源；普通语音回复不再自动推荐背景音。
- 背景音继续通过现有 `/api/audio/:trackId` 提供。

### 前端播放器

- 使用一个统一的播放控制器管理 `voice`、`background` 和 `voice_with_background`。
- `voice_with_background` 在浏览器端用 Web Audio API 将 TTS 和背景音混合，背景音自动降低音量，故事/冥想结束后停止两路音频。
- 发送按钮状态统一为：纸飞机（发送）、播放（三角形）和停止（方块）。
- 新音频开始前停止旧音频；播放被浏览器拦截时保留播放按钮，让用户轻触后继续。
- 播放错误只影响语音，不阻断文字回复。

## 记忆与冷却

- 当前会话保存推荐是否已展示、用户是否拒绝以及当前播放模式。
- 使用现有记忆系统记录背景音偏好和反馈，不新增独立用户身份体系。
- MVP 先做会话级冷却；长期记忆可在后续根据多次明确反馈形成稳定偏好。

## 验证标准

- 普通消息返回 TTS，但不自动附带背景音推荐。
- 用户明确要求背景音时只选择安全目录中的音频。
- 故事/冥想 + 背景音能同时播放，并可用同一个停止按钮结束。
- 主动推荐在高相关场景最多出现一次，拒绝后不重复打扰。
- 前后端测试覆盖模式选择、推荐冷却、音频响应和播放按钮状态。
